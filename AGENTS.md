# AGENTS.md — AGENT DATA CRM

## Scope
Independent project, not a Foundry subproject. Work with authorized native tools only; no AIOS, no fixed machine or model. Drive is canonical for business work, current decisions, execution packages and outputs. Git is for versioned code and reusable technical contracts. Do not add parallel trackers or store raw operational/customer data here.

## Restore before acting
For first use on the company seat, read [START-HERE.md](START-HERE.md), verify actual connected accounts and required capabilities, reconcile the plan with the user, then proceed with the current ROOT/RUN checkpoint. The bootstrap is not a global acceptance gate or a second state store.

2. Read Engine: https://docs.google.com/document/d/1QnKIsjpOlHHanrfg95EitYn5x0GS2G5E8XVY5gQXx3c/edit
3. Read RUN: https://docs.google.com/document/d/1kArPW1lkVozIMOuHgmBxs47Ev81okTL52VtmGZuo-og/edit
4. Check actual current account access, relevant business sources and current workbook metadata/revision. Never assume permissions. Resolve new requests by meaning and source, reuse existing IDs and completed work. Create a new record only for a distinct authorized deliverable.
5. Replan only affected work and dependencies from real priorities, deadlines if known, new instructions, meetings, capability changes. Preserve accepted work, owner input and unknown state.

**Method update — 2026-11-27:** After restoring the current ROOT/RUN checkpoint, the owning session reads [the scoped Shin method notice](docs/SHIN-METHOD-UPDATE-20261127.md), compares it with its existing R1/R2 practice, and records any adoption in the existing owner source. Delivery alone is not evidence of adoption.

## Execution
Select a useful scoped action, determine output/checks and actual permission/capability. Execute through authorized tools. For side effects record intent; inspect before retrying uncertain outcomes. Verify actual artifact or result, read current revision and serialize overlapping writes, commit linked receipt once and read back. Mark only the scope whose conditions are met. Business acceptance and actual CRM release remain separate from content preparation.

Use [docs/ADAPTER.md](docs/ADAPTER.md) and [adaptive policy](config/adaptive-contract.json). Continue independent branches when one is blocked. Keep user-facing communication in natural Vietnamese; internal identifiers only when helpful. Do not make the user enter spreadsheets for the Agent.

## Evolve
Evidence-linked scoped method improvement from actual feedback/results. Keep version history, relevant checks and rollback reference. Do not silently rewrite business decisions, permissions, accepted work or executable core. No final Operator acceptance gate; no mandatory alternate-host demonstration. For code changes run tests and clearly distinguish fixture evidence from actual host/CRM behavior.

## Safety
No credentials or customer content in Git, no unapproved external sharing, no production CRM writes without the relevant authority and actual permitted tools. No autonomous future run implied.
